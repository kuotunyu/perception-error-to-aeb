# Post-hoc addendum to v1.0.0 (not pre-registered; partly computed before writing)

**Status: post hoc, not pre-registered, and partly computed before its plan was written.** The [addendum plan](addendum-plan.md) was merged before any addendum number on this page was computed for publication, but after the released v1.0.0 results had been seen and after the scratch analyses that the plan lists. Nothing here is blind.

- **Every number on this page is post hoc,** except the released v1.0.0 `collisions` and `contacts_not_at_fault` of `oracle_aeb`, quoted beside the results that involve it, which come from [`evaluation.json`](../../evidence/nuplan_aeb_v2/evaluation.json). Items marked *computed before this plan* repeat a quantity that one of those scratch analyses had already computed from the same released records; the value shown is the one the addendum code computed in the pinned container.
- **Directions were known.** The released Shapley means and configuration levels were published in v1.0.0, so the direction of every Shapley difference and configuration contrast below was known in advance.
- **Estimation only.** No hypothesis is tested, no p-value is computed, and no ranking is declared among any channels.
- **What it covers.** The released v1.0.0 records only, that is controller v1 as released, including its target selection that is not path-gated. It changes no released number, claim, figure, tag or release, and it says nothing about the pre-registered [policy v2 study](../../studies/aeb-policy-v2/analysis-plan.md).

## Computed before this plan

Before the plan was written, scratch analyses of the local released records, run with numpy outside the pinned container, computed the following. Each is recomputed here by the addendum code and marked where it appears.

- the braking share of every released configuration (the braking-share contrasts);
- token-level collision counts, including the overlap between the collision tokens of `no_aeb` and those of `oracle_aeb` (the collision-indicator contrasts, and the collisions the released oracle AEB avoids and induces);
- token-level percentile intervals for all eight released Shapley values (the Shapley values, whose intervals this page computes with the log-cluster bootstrap instead);
- the distribution of matched onset delays in `coalition-none` and the three latency configurations (the matched onset delays);
- the brake-activation count of `oracle_aeb` (its row of the brake activations);
- whether the replicates of every token give identical results in `no_aeb`, `oracle_aeb`, `coalition-none`, `latency-medium` and `dropout-medium` (used here only to count the avoided and induced collisions as tokens);
- Clopper-Pearson bounds for the configurations with zero counted collisions.

## Question

How uncertain are the released Shapley values and configuration differences? How large is the localization-and-shape channel's Shapley value relative to each other channel's, in each released game?

## Reproduction gate

Before computing anything, the addendum code checked the released per-token records against the hash list written after the formal run finished, and it refuses to go on unless that list's own digest is the one the addendum plan states. It then recomputed, with float equality, every estimate, bound, confidence, resample count and seed in [`intervals.json`](../../evidence/nuplan_aeb_v2/intervals.json), every value and efficiency residual in [`shapley.json`](../../evidence/nuplan_aeb_v2/shapley.json), and `collisions`, `contacts_not_at_fault`, `simulated_seconds` and `mean_intervention_duration_s` of every configuration in [`evaluation.json`](../../evidence/nuplan_aeb_v2/evaluation.json).

The gate passed. No listed record was missing, extra or different, and no recomputed value differed from the released one. The outcome and its counts are `reproduction_gate` in [`evidence/addendum-summary.json`](evidence/addendum-summary.json), beside the hash list's digest as `released_output_hashes_sha256`.

## Data and method

- **Records.** The per-token records of the v1.0.0 formal run, kept outside Git under the nuPlan licence; only aggregates are published here. Every configuration uses the same `common_valid_tokens` = 344 <!-- claim: p3.posthoc.v1-addendum.common_valid_tokens --> tokens.
- **Shapley values.** Exact per-token Shapley values over the sixteen medium coalitions, computed on replicate means and averaged over tokens, for the two released games, `intervention_duration_s` and `collision_indicator`. The reference is `coalition-none`, not the oracle; its zero-severity tracker still differentiates positions.
- **Resampling.** A family-stratified log-cluster bootstrap. A cluster is one nuPlan log within one family; a log with tokens in several families forms a separate cluster in each, so the bootstrap carries no within-log correlation across families. Within each family its clusters are resampled with replacement, and one draw is shared by every configuration and game: `clusters` = 198 <!-- claim: p3.posthoc.v1-addendum.bootstrap.clusters -->, `resamples` = 5000 <!-- claim: p3.posthoc.v1-addendum.bootstrap.resamples --> draws, `seed` = 20260831 <!-- claim: p3.posthoc.v1-addendum.bootstrap.seed --> for numpy's PCG64 generator.
- **Intervals.** Two-sided percentile intervals, with numpy's linear interpolation. The six differences of the next section each get a simultaneous Bonferroni interval at `confidence` = 0.9917 <!-- claim: p3.posthoc.v1-addendum.difference.intervention_duration_s.localization_shape-minus-dropout.intervals-0-confidence; rounded: 4 --> and, beside it, one at `confidence` = 0.95 <!-- claim: p3.posthoc.v1-addendum.difference.intervention_duration_s.localization_shape-minus-dropout.intervals-1-confidence -->; every other interval on this page is at `confidence` = 0.95 <!-- claim: p3.posthoc.v1-addendum.configuration_contrasts.collision_indicator.oracle_aeb-minus-no_aeb.intervals-0-confidence -->.
- **Rounding.** Values are shown to three significant figures, keeping every integer digit, and exposure in seconds and onset delays to one decimal; the Bonferroni confidence is shown to four decimals, and the exact zero lower bounds of the Clopper-Pearson intervals are shown unrounded. The attribution audit recomputes each rounded value from its claim in [`claims.yaml`](claims.yaml), and the exact values are in [`evidence/attribution-addendum-evidence.json`](evidence/attribution-addendum-evidence.json).

## Error keying and dropout

In the released run one error key, which carries the configuration's dropout severity, seeds the dropout, localization/shape and track-instability draws ([simulation contract](../../simulation-contract.md#known-controller-and-modelling-choices)). Each marginal contribution of dropout to a coalition that contains localization_shape or track_instability therefore also redraws those channels' noise; at zero severity those two channels add no noise. φ(dropout), and every difference below that involves dropout, combines the dropout effect with a new noise realisation. The intervals include that variation and do not separate it.

## What this addendum does not show

- It describes controller v1 as released, including target selection that is not path-gated. It says nothing about policy v2.
- φ(dropout) and every difference that involves dropout combine the dropout effect with a redraw of the localization/shape and track-instability noise (see Error keying and dropout).
- Every cohort token was admitted by a straight-line, current-heading predicate on oracle tracks (`src/aebrisk/cohort/prefilter.py`). The cohort is not a sample of all driving, and the intervals describe resampling over its logs, not over driving in general.
- This is a simulation of non-reactive logged traffic: logged actors do not react to the ego, and a contact while the ego is stopped is recorded in `contacts_not_at_fault`, not as a counted collision. It says nothing about real-world AEB performance.
- The analysis was chosen after the released results had been seen. Apart from the Bonferroni adjustment over the six differences, the intervals are not adjusted for that or for how many are shown.
- It gives no channel ranking, no real-world AEB claim and no regulatory claim.

Each ran with a compose override, kept outside the repository, that mounts the released records and their hash list read-only under `artifacts/`, and with `-T`, which allocates no terminal:

```bash
docker compose -f compose.yaml -f <override> run --rm -T dev uv run --frozen aeb-risk study addendum --released-root artifacts/formal/nuplan_aeb_v2 --released-hashes artifacts/d2-operations/d2-nuplan-aeb-v2-20260906T165808Z-a65ae17/output-hashes.json --evidence-dir docs/evidence/nuplan_aeb_v2 --manifest docs/evidence/nuplan_aeb_v2/cohort/evaluation.json --eligibility docs/evidence/nuplan_aeb_v2/cohort/evaluation-eligibility.json --output artifacts/posthoc/nuplan_aeb_v2-addendum/addendum-summary.json
docker compose -f compose.yaml -f <override> run --rm -T dev uv run --frozen aeb-risk study evidence --part addendum --addendum artifacts/posthoc/nuplan_aeb_v2-addendum/addendum-summary.json --output-dir docs/posthoc/nuplan_aeb_v2-addendum/evidence
docker compose -f compose.yaml -f <override> run --rm -T dev uv run --frozen aeb-risk study claims --part addendum --evidence-dir docs/posthoc/nuplan_aeb_v2-addendum/evidence --output docs/posthoc/nuplan_aeb_v2-addendum/claims.yaml
```

`study evidence` copies the numbers of the summary and recomputes none, and it refuses any string shaped like a scenario token. Only aggregates are published: no per-token table, token identifier or scenario list.

These checks need no dataset. `tests/contract/test_posthoc_v1_addendum.py` pins the SHA-256 of the committed summary, derives the evidence from it byte for byte, checks that no token identifier appears in this directory, and runs both audits below. The Pages build runs the same audits before it publishes the site:

```bash
docker compose run --rm dev uv run --frozen aeb-risk audit-claims --claims docs/posthoc/nuplan_aeb_v2-addendum/claims.yaml
docker compose run --rm dev uv run --frozen python .agents/skills/auditing-aeb-error-attribution/scripts/validate_attribution.py --claims docs/posthoc/nuplan_aeb_v2-addendum/claims.yaml --repo-root . --document docs/posthoc/nuplan_aeb_v2-addendum/results.md
```
