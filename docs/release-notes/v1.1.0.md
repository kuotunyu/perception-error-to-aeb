# v1.1.0 發布說明

這個版本加入兩份建立在 v1.0.0 formal records 上的新分析：預先註冊的 AEB policy v2 研究，以及對 v1.0.0 的事後補充分析。v1.0.0 的 evidence、claims registry、release notes、protocol 與 tag 都沒有改動，cohort 也沒有重新選樣。

## AEB policy v2 研究（預先註冊）

v1.0.0 發布後檢查煞車結果時發現，released AEB 會對必要減速度最高的觀測物件煞車，不論該物件是否在 ego 的路徑上。這項研究在同一個 evaluation cohort 上重新做 closed-loop 模擬：policy v2 只允許 AEB 選取沿 ego 目前航向的直線 rollout 預測會與 ego 重疊、且中心不在 ego 後方的物件，其餘規則不變。速度估計（constant-velocity Kalman filter）與誤差抽樣的 keying 另外做成獨立的比較，不與 policy 的改變混在一起。

- 分析計畫在任何 variant 模擬之前凍結，凍結點是加入它的 pull request 的合併。該 pull request、merge commit 與合併時間，以及每個 arm 的 tooling commit、container image 與起訖時間，都記錄在 `docs/studies/aeb-policy-v2/evidence/reproduction.json`。
- 所有 gate 都通過：在研究涵蓋的每個 cell 上，arm A 的每份 per-token document 都與 v1.0.0 同 cell、同 token 的 document 逐位元相同，因此結果不是 exploratory。
- Q1 問的是：已發布的煞車時間有多少來自 AEB 選取煞車目標的規則。依預先固定的判定規則，Q1 的標籤是 Partial support：在 oracle 感知下，以及所有誤差 channel 都設為 medium 時，改用 policy v2 後煞車時間占比都下降，兩項下降也都通過預先固定的檢定，但後者的降幅未達 Support 要求的門檻。這個標籤說明已發布的煞車時間從哪裡來，不是對控制器表現的評價。
- 碰撞相關的兩個假設都是 not established，這不等於沒有影響。H5 問的是：在 oracle 感知下，policy v2 是否改變計入碰撞；研究沒有偵測到變化。H4 問的是：v1.0.0 在所有誤差 channel 都設為 medium 時沒有出現任何計入碰撞，這個結果是否取決於已發布的目標選取規則。policy v2 在這個設定中有部分 token 出現計入碰撞，但 sign-flip 檢定未達預先固定的門檻，所以研究沒有顯示這個結果取決於該規則。
- 結果頁、claims registry、evidence 與 operator log：[docs/studies/aeb-policy-v2/](https://github.com/kuotunyu/perception-error-to-aeb/blob/v1.1.0/docs/studies/aeb-policy-v2/results.md)。

## v1.0.0 事後補充分析（未預先註冊）

為 v1.0.0 的 Shapley 值、其差值與選定的設定差值補上 paired intervals；只做估計，不做檢定，也不做 channel 排名。這份分析不是預先註冊的，部分數值在撰寫計畫前已經算過。它有自己的 reproduction gate：先以 float 完全相等重現已發布的 intervals、Shapley 值與 evaluation 欄位，才計算任何新數字；它也有自己的 claims registry。

- 計畫與結果：[docs/posthoc/nuplan_aeb_v2-addendum/](https://github.com/kuotunyu/perception-error-to-aeb/tree/v1.1.0/docs/posthoc/nuplan_aeb_v2-addendum) 中的 `addendum-plan.md` 與 `results.md`。

## 限制

兩份分析都建立在對不會反應的 logged traffic 所做的模擬上，不代表實車 AEB 的表現，也不主張符合任何法規或標準。
